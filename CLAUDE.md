# Solfège Piano : notes spécifiques au projet

Expo SDK 58 (React Native 0.88, React 19.3), TypeScript strict, Expo Router (`typedRoutes`), alias `@/*` → `src/*`. Code, commentaires et textes en français. Gestionnaire : npm (`package-lock.json`), pas bun. Écrans de jeu en paysage (`orientation: default`).

## Commandes du projet
- `npm run typecheck` (`tsc --noEmit`), `npm run lint` (`expo lint`) : ce que fait aussi la CI avant `npm test`.
- `npm test` : trois scripts `tsx` en `node:assert` (`scripts/tests/{lecons,exercices,polyphonie}.test.ts`, lançables seuls avec `npx tsx …`). Le test de polyphonie décode `assets/sounds/piano_*.mp3` avec **ffmpeg** (à installer en local ; la CI l'installe). `scripts/tests` est exclu de `tsconfig.json` : non vérifié par `typecheck`.
- `npm run sons` (ffmpeg + réseau) télécharge les échantillons Salamander (`tonejs.github.io/audio/salamander/`, cache dans le dossier temporaire) et régénère `assets/sounds/piano_36..96.mp3` (Do2 à Do7, mono, 2,6 s avec fondu ; un échantillon par tierce mineure, les notes intermédiaires sont transposées d'un demi-ton au plus), les deux clics du métronome et **`src/audio/samples.ts`** (`require` statiques exigés par Metro : ne pas l'éditer à la main).
- `npm run icones` (Python + Pillow) régénère les icônes de `assets/`. Les deux scripts de génération figurent dans `.gitignore` bien qu'ils soient suivis par git.
- `npx expo start --web` : version navigateur pour développer (micro et rendu y diffèrent du téléphone).

## Architecture
- `src/store/` : contextes `Reglages`, `Progression`, `Midi`, persistés en JSON dans AsyncStorage via `stockage.ts` (`lire` fusionne avec les valeurs par défaut ; erreurs ignorées). Clés versionnées `reglages-v1`, `progression-v1`, `midi-bluetooth-v1` : changer un format = changer le suffixe. Étoiles : précision ≥ 95 % → 3, ≥ 80 % → 2, ≥ 50 % → 1 (`calculerEtoiles`).
- Moteur de jeu `hooks/useMoteurJeu.ts` : temps en temps musicaux (noire = 1), boucle `requestAnimationFrame`. Notes regroupées par début (accord, deux mains) ; un groupe est réussi quand toutes ses notes sont jouées, dans n'importe quel ordre. Mode attente : arrêt sur le groupe, note acceptée jusqu'à 1,5 temps en avance ; mode libre : tolérance 0,3 s, sinon « manquée ». Source des notes : `ecran`, `micro` ou `midi`.
- Micro : `hooks/useMicro.ts` (flux PCM 44,1 kHz mono `float32` d'`expo-audio` `useAudioStream`, disponible dans Expo Go) + `music/polyphonie.ts` en TypeScript pur : FFT avec fenêtre de Hann, puis saillance harmonique à la Klapuri (2006) sur Do2 à Do7 (MIDI 36 à 96), 10 harmoniques, inharmonicité 0,0004, 6 notes simultanées au plus, note signalée à l'attaque. Réglages de calibration : `sensibiliteMicro` (0,5 à 2) et `bruitMicro`.
- Pièges du micro (`useMoteurJeu`) : l'octave n'est pas vérifiée (seul le nom de la note compte) ; une note qui est une harmonique (+12, +19, +24, +28, +31 demi-tons) d'une autre note de l'accord est validée avec elle, un micro ne peut pas les distinguer ; après un accord réussi, 250 ms d'écoute ignorée ; une même fausse note n'est comptée qu'une fois par 700 ms (résonance) ; seul le groupe courant est regardé, jamais le suivant ; le micro ignore les sons joués par l'appli (clavier, métronome : `ignorerUnInstant`, 500 ms par défaut).
- Clavier MIDI : module natif Expo `modules/clavier-midi` (Kotlin, `android.media.midi`, déclaré par `expo-module.config.json`, ses permissions Bluetooth sont dans son propre `AndroidManifest.xml`) ; absent d'Expo Go et d'iPhone, donc de l'APK seulement. `store/Midi.tsx` : USB connecté automatiquement, Bluetooth LE cherché dans les réglages puis reconnecté (dernier appareil mémorisé), Web MIDI (Chrome) sur le web.
- Notes : les noms suivent la notation internationale, `Do4` = do central = MIDI 60 (`DO_CENTRAL`) ; en France on dit souvent « Do3 ». Une couleur par note, la même partout (`theme/couleurs.ts`). `ecrireMidi(midi, armure)` choisit dièse ou bémol selon l'armure.

## Format des leçons (`src/data/niveaux/niveauN.json`, compilé par `src/data/lecons.ts`)
- Fichier de niveau : `niveau`, `titre`, `description`, `lecons[]`. Leçon : `id` (unique, ordre du fichier = ordre du parcours), `titre`, `description`, `cle` (`sol`, `fa` ou `double` = grande portée), `tempo`, `main` (`droite`/`gauche`), puis `notes` ou `voix`.
- Facultatifs : `armure` (dièses > 0, bémols < 0 ; écrire quand même `Fa#5`/`Sib4` : l'altération n'est affichée que si elle diffère de l'armure), `mesure` (`4/4` par défaut), `attente: false` (coupe le mode attente par défaut, utile pour le rythme).
- Note : `note` (`Do4`, `Sib3`, accord `Do4+Mi4+Sol4`, ou `silence`), `duree` en temps (4 ronde, 3 blanche pointée, 2 blanche, 1,5 noire pointée, 1 noire, 0,5 croche), et facultatifs `doigt` (1 pouce à 5 auriculaire, liste pour un accord), `nuance` (`pp`, `p`, `mp`, `mf`, `f`, `ff`), `lie` (prolonge la note suivante de même hauteur sans la rejouer), `main` (par note).
- Deux mains : remplacer `notes` par `voix`, liste de voix jouées ensemble ayant chacune `main` et `notes` ; avec `cle: "double"`, main droite en clé de sol et gauche en clé de fa. Le clavier affiché est déduit des notes.
- Nouveau niveau : créer `niveauN.json`, l'importer et l'ajouter à `SOURCES` dans `src/data/lecons.ts`. Le commentaire en tête de ce fichier renvoie au README pour le format, qui est décrit ici.

## Build, release, signature
- CI `.github/workflows/apk.yml` (chaque push, Node 22, JDK 21) : `npm ci`, `tsc`, `expo lint`, `npm test`, `npx expo prebuild -p android --no-install` (`android/` n'est pas versionné, il est généré à chaque build), `gradlew assembleRelease`, APK gardé en artefact. Sur la branche par défaut seulement : release `apk-<n° de run>` « Solfège Piano – dernière version » marquée dernière, puis suppression des anciennes `apk-*` (après la création, pour qu'un `SolfegePiano.apk` soit toujours téléchargeable). Lien : `https://github.com/p-bailly/Musique/releases/latest/download/SolfegePiano.apk`.
- `app.config.js` enveloppe `app.json` : `versionCode` = `GITHUB_RUN_NUMBER` (1 en local) pour que chaque APK s'installe par-dessus le précédent sans perdre la progression, et ajoute `plugins/signature-perso.js`.
- Ce plugin signe la release avec `keystore/solfege-piano.keystore` (alias `solfege`, mot de passe dans le plugin), **versionné exprès** comme pour NBA, Scan, Météo et Mes applis (usage perso, aucun secret à configurer), et ne compile que `armeabi-v7a` et `arm64-v8a`. Toujours la même clé : Android refuse une mise à jour signée autrement.
- Suivi par « Mes applis » (dépôt Managing-Apps, `TrackedApps.kt` : `p-bailly/Musique`, paquet `fr.solfegepiano.app`, fichier `SolfegePiano.apk`) : renommer le paquet ou l'APK casse ce suivi.
- Autres installations : Expo Go ne sert qu'à tester (pas d'icône propre, pas de MIDI). EAS (`eas.json` : profils `preview` = APK interne, `production` avec `autoIncrement`, `appVersionSource: remote`) : `npx eas-cli@latest login` puis `build:configure` une fois ; Android `build -p android --profile preview` (10 à 15 min, lien et QR code) ; iPhone : compte Apple Developer payant (99 €/an), `device:create`, `build -p ios --profile preview`, ou TestFlight avec `build -p ios --profile production && submit -p ios` ; sans compte payant, avec Mac et Xcode, `npx expo run:ios --device` (à réinstaller tous les 7 jours).
